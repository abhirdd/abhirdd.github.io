URL juxtaposition lab — trusted-domain string placement fuzz (internal engine testing)

Scope: internal download-UI hardening for YOUR engine. Each vector places the TRUSTED string at a different position of the URL syntax (scheme · userinfo · path · query · fragment · control chars) and dispatches a real download attempt. The core measurement is the triple RAW href → WHATWG parse → serialized a.href: a hardened engine renders only the re-serialized URL (userinfo stripped, control chars gone, punycode shown) in every security surface; a vulnerable engine renders the raw string or accepts an invalid parse. Payloads are inert .txt probes; server-dependent vectors point at your internal TESTHOST only. On stock Chrome: J1/J5/J9 produce no row at all and J2/J4/J10 attribute correctly — deviations in YOUR engine are the bugs you are hunting.

J0 — PARSE-ALL (no dispatch)

Runs every vector string through new URL() only. Shows exactly where the TRUSTED string lands in the parse tree (scheme / userinfo / host / path / query / fragment) before you dispatch anything.

J1 — SCHEME-DOT: TRUSTED:blob:null/<uuid>

Dots are legal scheme characters (WHATWG), so this parses as scheme = trusteddomain.com. Stock: unknown scheme → no DownloadItem. Your engine: if an item is created from the raw href, GetURL() == the juxtaposed string → scheme validation must precede item creation.

J2 — PATH-PREFIX (server): TESTHOST/TRUSTED/blob:null/<uuid>

TRUSTED string as a path segment; bytes come from TESTHOST. Tests what your URL display renders first and how truncation behaves (front-truncation = bug class).

J3 — FRAGMENT-PREFIX: TRUSTED#blob:null/<uuid>

Relative reference: resolves against your page host with path = TRUSTED and fragment = blob:… Tests fragment rendering and whether fragments bleed into any security surface.

J4 — USERINFO (server): https://TRUSTED@TESTHOST/jx.txt

The classic: bytes from TESTHOST, raw string reads TRUSTED first. Hardened: security surfaces strip userinfo (Chrome does); copy-link may show raw. Any surface that highlights TRUSTED as the host = display bug.

J5 — BLOB INNER-ORIGIN USERINFO: blob:https://TRUSTED@TESTHOST/<uuid>

Tests whether your blob-URL parser accepts userinfo inside the inner origin. It must not — inner origin has to parse strictly as a serialized origin.

J6 — BACKSLASH DIFFERENTIAL: https://TRUSTED\@TESTHOST/…

WHATWG converts \ to / in special URLs → host = TRUSTED, bytes go to the real trusted host. Engines using non-WHATWG parsers can connect elsewhere while displaying TRUSTED — the classic parser-differential class.

J7 — CONTROL-CHARS / BIDI: U+202E + CR/LF injected

WHATWG strips tabs/newlines from URL input and percent-encodes the rest; hardened UIs render only the sanitized serialization. Engines that render the raw href get bidi-overwrite and line-wrap display injection.

J8 — FULLWIDTH-SLASH: U+FF0F as separator

https://TESTHOST／TRUSTED／blob:null／<uuid> — fullwidth solidus is NOT a separator per WHATWG (stays percent-encoded in the path); non-conforming parsers may split the host there.

J9 — FORGED BLOB ORIGIN: blob:https://TRUSTED/<uuid>

Carryover from B3: must fail store lookup in every conforming engine. Any row appearing here = your BlobURLStore is not validating the inner origin.

J10 — QUERY-JUXTAPOSE (server)

TESTHOST/?from=TRUSTED&u=blob:null/<uuid> — bytes from TESTHOST, trusted string embedded in the query; tests whether query components get highlighted/truncated into "host-looking" prominence.

J11 — BLOB-FRAGMENT: blob:https://TESTHOST/<uuid>#TRUSTED:blob:…

Fragment attached to a blob URL carrying the full juxtaposed string. Fragments must never bleed into attribution or the From line — verify every surface.

J12 — WHITESPACE PADDING

Leading/trailing spaces around the href: the parser trims them; raw-rendering engines display padding tricks. Logs the raw vs serialized diff for the general raw-render check.

Hardening checklist for your engine (fix = pass all vectors):

1. Never render raw href strings in any UI — always re-serialize through the URL parser.

2. Strip userinfo in every security-relevant display.

3. Render punycode for non-ASCII hosts; refuse mixed-script confusables.

4. Truncate URLs from the END only — never front- or middle-truncate.

5. Strip/refuse control characters (CR/LF/TAB/U+202E-class bidi) in display strings.

6. Validate blob: inner origin strictly as a serialized origin (no userinfo, no path, no fragment bleed).

7. Reject unknown/unregistered schemes BEFORE creating a download item (blocks the J1 class).

8. Attribution ("From") must come from the browser-bound request initiator, never from URL fields.

Decision rule: any surface where TRUSTED reads as the host/source while bytes actually come from TESTHOST (or no row should exist but one does) = display/validation bug in your engine. Record the RAW → serialized → displayed triple per vector.
