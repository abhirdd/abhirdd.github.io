Chrome "From …" attribution spoof lab — target string: google.com (local only)

Research use only. Run locally against your own Chrome/Chromium builds. Any divergence you capture = candidate unpatched bug: file it via crbug.com / Chrome VRP before hosting or publishing anything. Payloads here are inert .txt probes; the executable-proof slot points at YOUR OWN hosted URL only.

Threat-model grounding (Chromium CL ae2cc7a, feature kDownloadsDisplayInitiatorOrigin, default ON): the post-fix "From" line renders FormatOriginForSecurityDisplay(download_item->GetRequestInitiator()). The initiator origin is bound browser-side to the origin of the document that executed the download — page-controlled levers (Referrer header, referrerpolicy, rel, redirect hops) do NOT feed it. It is omitted when: no initiator, no user gesture, or formatted origin > kMaxDisplayURLChars. With the feature OFF (kill-switch), the UI falls back to displaying GetURL() = the ORIGINAL request URL — which IS page-controlled and redirect-spoofable. Therefore exactly three spoof routes exist: R1 kill-switch fallback + redirect chain through a google.com hop; R2 formatting-layer tricks on an origin you own (userinfo / IDN homograph / trailing dot / long-origin omission); R3 a NEW divergence bug where Chrome mis-attributes initiator across contexts (opaque frames, cross-realm nodes, teardown). This lab machines all three routes and auto-structures the evidence for a report.

S1 — CONTROL (truth baseline)

One gesture download from the top document. Record the exact "From" string = your true origin. Every other vector is compared against this baseline.

S2 — REFERRER-LEVER REGRESSION (3 anchors, 1 gesture burst)

Fires 3 synchronous gesture downloads with referrerpolicy = unsafe-url / no-referrer / origin plus rel=noreferrer, and attempts a forbidden Referrer: https://www.google.com/ header via fetch (expect TypeError). Post-fix prediction: "From" IDENTICAL on all rows → referrer route is dead (regression check vs pre-patch).

S3 — R1 REDIRECT-CHAIN SPOOF (flag-gated)

Navigates to redirector + encodeURIComponent(target): original request URL = google.com hop, bytes arrive from your target. Flag OFF ⇒ "From" should render the google hop = SPOOF SUCCESS. Flag ON ⇒ "From" = your origin = patch holds. Run in both states (see S8 CLI) and log both rows.

S4 — R3 INITIATOR-CONTEXT MATRIX CYCLER

Each click fires ONE gesture download from the NEXT context: c0 top · c1 same-origin iframe · c2 srcdoc iframe · c3 about:blank iframe · c4 blob: iframe · c5 data: iframe · c6 about:blank popup (sync) · c7 sandboxed opaque iframe (msg, auto). Filename encodes context. Any row whose "From" ≠ that context's true origin = mis-attribution primitive (R3). 8 clicks = full matrix.

S5 — ADOPTED-REALM PROBE (cross-realm anchor)

Anchor+blob created in a popup realm, document.adoptNode() into top doc, clicked automatically. Prediction: "From" = top origin (click-dispatching doc wins). If it renders the popup/creator realm instead → realm-confusion primitive.

S6 — OPAQUE-LAUNDER PROBE (gesture inside sandbox)

Visible sandboxed srcdoc iframe (origin==="null"); you click INSIDE it, so the download is gesture-flagged with an opaque initiator. Watch the row: empty/null = patch holds; top-document origin = launder bug (opaque context credited with parent's identity — the primitive that would make google.com-style spoofing possible from any embedded context).

S7 — R2 FORMATTING-FUZZ GENERATOR (hosted-only recipes)

Builds the exact origin strings to serve THIS lab from on a domain you own, then gesture-download and read "From": (a) userinfo https://google.com@YOURHOST/ link-display probe, (b) trailing dot https://YOURHOST./, (c) IDN homograph candidates list, (d) long-origin padding: generates a ≤253-char subdomain chain (>kMaxDisplayURLChars ⇒ "From" omitted even for gesture downloads = attribution blackout). Copy outputs, host, test.

S8 — KILL-SWITCH A/B HELPER (R1 enabler)

Copies exact Chrome launch commands for flag ON vs OFF so you can run S3 in both states and diff the "From" row. OFF: --disable-features=DownloadsDisplayInitiatorOrigin; ON: --enable-features=DownloadsDisplayInitiatorOrigin. Use a FRESH --user-data-dir per state so the flag actually applies.

S9 — URL-CHAIN LEAK PROBE (post-S3)

After an S3 run: in the bubble / chrome://downloads, (1) read the "From" line, (2) right-click row → copy link address, (3) expand details for full URL chain. Record all three in the table: divergence between displayed attribution and chain = evidence of which surfaces still leak the google hop (needed for a complete report).
